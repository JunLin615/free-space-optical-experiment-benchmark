# Bounded semantic judge and calibration

`benchmark/judge/bounded_v0.1.json` pins the prompt, version, deterministic sampling settings, output budget, and required JSON fields. `tools/semantic_judge.py` accepts a backend from an external runner. It sends one criterion at a time, treats candidate text as untrusted data, blinds candidate model identity by excluding it from the request, requires a short quote found in the candidate response, and returns `pass`, `fail`, or `unresolved`. Failed deterministic gates bypass the judge. Missing backend, malformed output, unsupported wording, or ungrounded evidence resolves to `unresolved`, never a guessed score.

`benchmark/judge/calibration_v0.1.json` contains correct, wrong, physically wrong, incomplete, alternative-valid, borderline, and prompt-injection challenges for prospective residual diagnostic and weak-signal criteria. A live calibration run must record multiple independent verdicts per item and supply the map to `python tools/calibrate_judge.py --responses path/to/responses.json`. The command reports false-pass rate on known negatives, false-fail rate on known positives, unresolved rate across all items, and instability rate across repeated runs. Expected-borderline `unresolved` is retained in the set and contributes to overall abstention.

Release threshold per semantic criterion: at least 50 positive and 50 negative judge runs; **zero** false passes on negatives, at most 5% false fails on positives, at most 10% unresolved overall, and no repeated-item instability. These are minimum empirical gates, not a statistical guarantee. A changed prompt, model, sampling setting, or criterion invalidates old calibration evidence and requires a new version and rerun. The current small set and offline mock tests cannot meet the sample-size gate; no semantic criterion is release-ready in this round. Narrow or replace an unreliable semantic check with executable evidence before promotion. Normal scoring never routes to a human reviewer.
